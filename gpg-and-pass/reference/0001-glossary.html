GPG & pass vocabulary

The words these tools use, defined once. Every lesson in this workspace uses them in exactly these senses.

Entries marked † are terms whose everyday English meaning differs from their OpenPGP meaning. Those are the ones that cause trouble.

Keys

TermDefinition
Keypair A public key and its matching private key. The public one locks data; only the private one unlocks it.
Primary key The root keypair of your OpenPGP identity. Listed as pub (public half) or sec (secret half). Normally capable of certify and sign, and by default not encryption.
Subkey A separate keypair bound to the primary by a certification signature. Listed as sub / ssb. Does the day-to-day work; can be revoked and replaced without changing your identity.
Capability What a key is allowed to do, shown in brackets: [C] certify, [S] sign, [E] encrypt, [A] authenticate. Source of truth: /usr/share/doc/gnupg/DETAILS, field 12.
Fingerprint 40 hex digits uniquely naming one key. The unambiguous way to refer to a key.
Key ID An abbreviation of the fingerprint: its last 16 hex digits (long form) or last 8 (short form). Convenient, and short IDs are collidable — prefer fingerprints when precision matters.
User ID (uid) A human label bound to a key, conventionally Name <email>. A key may carry several. This is the name pass looks up.
Keygrip GnuPG's internal 40-hex handle for a stored private key, used as the filename in private-keys-v1.d/. Not an OpenPGP concept; you will rarely need it.
Revocation certificate A pre-signed statement declaring a key dead. Generated at key creation and stored in openpgp-revocs.d/. Your only recourse if the private key is lost.
Trust † In GPG, trust means "how much do I believe this key belongs to that person" — a web-of-trust concept, not a measure of security. Your own key shows [ultimate] because you made it.
Recipient A key that a given ciphertext was encrypted to. A file can have several, which is how team stores work.

GnuPG machinery

TermDefinition
GnuPG / GPG The free implementation of the OpenPGP standard. gpg is the command; version 2.x is current.
OpenPGP The standard (RFC 4880 and successors) that GnuPG implements. Distinguishes the format from any one program.
Keyring Your local collection of keys. Historically files like pubring.kbx.
keyboxd The newer public-key storage daemon in GnuPG 2.4+, keeping keys under public-keys.d/ instead of a single pubring.kbx. Default on 2.4+ installs — check with ls ~/.gnupg. Where it is in use, guides saying "copy your pubring.kbx" do not apply.
gpg-agent The background daemon holding private keys and caching passphrases. The reason you type your passphrase once and not on every pass show.
pinentry The helper program that actually prompts for your passphrase. Comes in curses, GTK and Qt flavours; which one runs is a gpg-agent setting.
Passphrase † The secret protecting your private key on disk. It is not an encryption key for your passwords and it is never stored in the password store.
Armor ASCII-safe base64 wrapping (--armor), producing -----BEGIN PGP…----- text. Needed when a key must travel through something that mangles binary.

pass

TermDefinition
pass "The standard Unix password manager": a shell script over gpg, git and the filesystem. Each secret is one GPG-encrypted file.
Password store The directory tree of encrypted files, by default ~/.password-store. Overridable with PASSWORD_STORE_DIR.
pass-name A secret's path within the store, without the .gpg suffix — e.g. work/aws/prod. Directory structure is yours to invent.
.gpg-id A plain-text file listing the recipients (one per line, by uid or fingerprint) that secrets in this directory are encrypted to. Written by pass init.
Per-directory recipients A subdirectory may hold its own .gpg-id, overriding the parent's for everything beneath it. The mechanism behind scoped team access.
Re-encryption When the recipient list changes, pass init decrypts and re-encrypts every affected file to the new set. Note this requires the private key.
Multiline entry Convention, not enforcement: line 1 is the password, subsequent lines hold metadata (username:, url:, …). pass show -c copies line 1 by default.
Extension An add-on subcommand, e.g. pass-otp. Enabled per-store via PASSWORD_STORE_ENABLE_EXTENSIONS=true and .extensions/.

The distinction worth internalising

Your passphrase unlocks your private key. Your private key decrypts your secrets. Three different things, and conflating the first two is the most common way people talk themselves into a mistaken backup strategy.
