Rego & Conftest · Reference 1

Glossary

The vocabulary, defined once. These are the words used consistently across every lesson — and the words to use when you explain this to someone else. It grows as the course does; conftest's own vocabulary joins it once we get there.

Terms marked † are ones people routinely get wrong. If you are preparing a session for coworkers, budget extra time for those.

The document model

TermMeaningIn practice
Document A JSON value. Everything in Rego — input, output, intermediate results — is one. The unit of everything. "Rego builds documents" is the whole model.
Base document Data that arrives from outside OPA: your config file, or data files loaded from disk. Your parsed deployment.yaml, or a JSON file of allowed base images.
Virtual document Data computed by rules. Does not exist until evaluation runs. Every key your .rego file produces, including deny.
input † The global holding the document currently being evaluated. Exactly one per evaluation. The JSON you are asking about, e.g. {"age": 21}.
data † The global root under which everything else lives — loaded data files and all rule output, addressed identically. opa eval 'data' prints the whole thing. Your best debugging tool.
Query An expression you ask OPA to evaluate against the document. data.example.allow asks for one rule's output.

The distinction to hammer

input goes in; data comes out (and also holds static reference data going in). A rule that reads data.main.deny when it meant input.spec is the most common beginner mix-up.

Rule anatomy

TermMeaningLooks like
Package The namespace a file's rules are built under. Determines the address of the output. package main → output at data.main.*
Rule An instruction for building one key in the document. allow if input.user == "admin"
Rule body The expressions inside { … }. All must hold — it is an AND. Two lines in a body means both conditions.
Complete rule † Assigns a single value to its key. If the body fails, the key is undefined. replicas := input.spec.replicas
Partial / multi-value rule † Contributes members to a set. Many bodies may contribute; zero contributions is a valid empty set. Unlike a complete rule, it is always defined. deny contains msg if { … }
Incremental The docs' word for several definitions of one rule name: each is additive, so they collect rather than conflict. Order in the file is irrelevant. Three deny contains … rules build one deny set.
Default rule A fallback value used when every other definition of that rule is undefined. default allow := false

Evaluation states

Undefined is not false, and false is not empty. Three distinct states, and conflating them is the number-one source of policies that silently pass.

StateWhat it meansIn the document
Undefined † A rule body did not hold, so the rule produced no value at all. The key is absent. opa eval on it prints undefined.
false A rule successfully produced the boolean false — usually via default. "allow": false — the key exists.
Empty set A multi-value rule ran and nothing contributed. "deny": [] — the key exists, and this is what a pass looks like.

Logic: AND and OR

AND goes down. OR goes sideways. Rego has no and or or keyword: expressions stacked in one body are conjoined, and definitions sharing one rule name are disjoined.

TermMeaningLooks like
Conjunction (AND) Every expression in a body must hold. One undefined expression silences the rule entirely — including an undefined msg :=. Two lines inside { … }. A ; is the same separator; opa fmt rewrites it to a newline.
Disjunction (OR) † Any one definition holding is enough. Written by repeating the rule name — see Incremental above. Two deny contains msg if { … } blocks with the same message.
Guard A leading expression that filters which documents the rule speaks about. A filter, not an assertion: a guard naming a kind that never appears makes the rule silently unreachable. input.kind == "Deployment" as the first line of a body.
Helper rule An ordinary rule holding no message, used as a named condition inside other bodies. Defined twice, it is a named OR. Conftest does not count it. replicated_workload if input.kind == "Deployment"
Dead rule † A rule whose body can never hold — classically two equalities on one field, written meaning OR. Compiles, is counted in the report, never fires. Only a failing fixture catches it. input.kind == "Deployment" AND input.kind == "StatefulSet"

Three spellings of one OR, in order of preference: alternatives that are only values → x in {"a", "b"}; alternatives that are conditions, used once → two rule definitions; the same condition used by several rules → a helper.

Language mechanics

TermMeaning
:=Assignment. Binds a new local variable; re-binding the same name in one scope is an error.
==Comparison. Both sides must already be known.
= †Unification: assign-or-compare, whichever the situation calls for. Prefer := and == until you know why you want this.
UnificationSolving for whatever bindings make both sides equal. The engine's core operation.
someDeclares a variable as free, to be searched over. some x in arr.
everyAsserts a condition holds for all members of a collection.
_Anonymous iteration variable. arr[_] means "any element of arr".
contains †Makes a rule a partial set rule. s contains x if b reads "when b holds, x belongs to s".
Set †Unordered collection, no duplicates. Rego's one type that JSON lacks — OPA serialises it as an array on output, which is a printing detail, not an ordering promise.
inMembership. x in s holds when x is a member of the collection s.
sprintf()Builds a message string: sprintf(format, values) — exactly two arguments, the second an array. %s string, %d integer, %v anything.
count()Size of a collection. count(deny) == 0 is the idiomatic "did it pass?".
SafetyA compile-time guarantee: every variable must be bound by a non-negated expression somewhere. This is why not on an unbound variable is a compile error, not a runtime surprise.
Rego v1 †The current language version (OPA ≥ 1.0). if and contains are mandatory. Pre-2024 examples on the web are mostly v0 and will not parse.

Conftest

Conftest introduces no Rego. Every term here is a convention it layers on top of the language — which is why the whole section fits in one table.

TermMeaning
ConftestA CLI that parses config files into input, evaluates your Rego against each one, and turns the result into an exit code. A wrapper around opa eval, not an engine.
Namespace †Conftest's word for the Rego package it queries. Default main. Nothing to do with Kubernetes namespaces — a permanent source of confusion when teaching this to a Kubernetes team.
denyA partial set rule whose members are failure messages. Any member exits 1.
violationExact synonym for deny. Pick one and use it consistently.
warnSame mechanism, reported but not reflected in the exit code — unless --fail-on-warn.
Rule suffix †deny_replicas, warn_labels. An underscore plus an identifier; conftest finds these too. Not merely cosmetic — an exception names the suffix, so only suffixed rules can be excepted.
ParserThe component that turns a config file into the JSON input. Chosen by extension, forced with --parser. conftest parse FILE shows you its output.
Document (conftest sense) †One parsed unit of input. A multi-document YAML file yields several, each evaluated separately — your rules never see two at once without --combine.
--combinePasses all documents at once as an array of {"path": …, "contents": {…}} objects — so input changes shape and existing rules stop matching. The only way to write a cross-file rule.
ExceptionAn exception contains rules if … rule whose members are lists of rule suffixes (["replicas"] excepts deny_replicas). Reported as EXCP and counted in the last column.
0 tests †Not "everything passed". It means no rules were found at the queried address — usually a package that is not main. Exits 0, so CI must check for it explicitly.
